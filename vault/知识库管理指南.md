## 📋 Frontmatter 规范

**源文章模板：**
```yaml
---
创建时间: "YYYY-MM-DD"
tags: ["标签1", "标签2"]
类型: "分类名"
状态: "#待整理 / #已整理"
来源: "URL"
作者: "作者名"
摘要: "一句话概括"
---
```

**Wiki 概念页模板：**
```yaml
---
创建时间: "YYYY-MM-DD"
tags: ["wiki", "概念"]
类型: "Wiki"
状态: "#已整理"
摘要: "一句话概括"
---
```

**规范要点：**
- 所有字段值双引号包裹，`tags` 用 YAML 数组
- 摘要字段禁止使用中文双引号 `""`，改用单引号 `''`
- 正文末尾写 `**关联文章**` + 逐行 `[[链接]]`

## 🏥 核心工作流

### Git 版本控制铁律

每次操作文件前，必须执行：
1. **`scripts/git_control.py pre "<操作描述>"`** — 任务前快照
2. **操作完成**后，立即执行 **`scripts/git_control.py post "<操作描述>"`** — 任务后提交

**提交信息格式：**
| 前缀 | 场景 |
|------|------|
| `🔄 [pre]` | 任务前快照（自动生成） |
| `📝 [post]` | 任务后提交 |
| `🔧 [plugin]` | 插件安装/配置 |
| `📖 [rule]` | 规则文件更新 |
| `🔗 [link]` | 双链调整 |
| `📂 [file]` | 文件移动/结构变更 |

**权限分区：**
| 区域 | 路径 | 权限 |
|------|------|------|
| 🔵 活动区 | `00-收件箱/` | 自由创建/修改/移动（建链在此完成） |
| 🟡 只读区 | `01-素材库/` | 入库流程禁止碰，`safe_link_appender` 硬拦截，用户授权除外 |
| 🟢 半只读 | `02-Wiki/` | 允许追加关联文章 + `_index.md` 追加条目 |
| 🟡 只读 | `03-思考/` `04-项目/` `05-产出/` | 需用户明确授权 |
| 🔴 禁止 | `06-系统/` | 禁止修改，除非用户明确允许 |

**回滚方法：**
- 恢复单个文件：`python scripts/git_control.py restore "00-收件箱/xxx.md"`
- 回滚到上一版本：`python scripts/git_control.py rollback`

### 入库流程 v4.2

> **三阶段**：整理入库（留在收件箱）→ 编译 Wiki → 脚本建链 → 移动归档

当用户说"入库"时，严格按以下顺序执行：

**阶段一：整理入库**

0. **读规则** — 读取本文件 + AGENTS.md
1. **⚠️ Git 快照** — `python scripts/git_control.py pre "入库整理"`
2. **读模板** — 读取 `06-系统/模板/新笔记.md`
3. **扫描收件箱** — 列出 `00-收件箱/` 下所有笔记
4. **阅读内容** — read_file 读正文，不凭标题猜
5. **提出分类建议** — 只提分类，不含链接建议（链接留到阶段三）
6. **用户确认后操作**：
   a. 改 frontmatter，按模板格式填充
   b. 清理残留行（`^作者[:：]`/`^时间[:：]`/`^来源[:：]`/`^\d+ 人赞同`等）
   c. 正文末尾写 `**关联文章**\n\n（待统一建链）`
7. **自检** → 不通过则 rollback + 错误日志 + 终止
8. **文件暂留收件箱** — 不移动，Git 提交标注 `"入库整理（待建链）：N 篇"`

**阶段二：编译 Wiki**

9. **扫描匹配** — 遍历 `02-Wiki/` 判断新文章匹配哪个概念页
10. **提 Wiki 变更方案** — 表格列出，等用户审核：

    | 文章 | 操作 | 目标 |
    |------|------|------|
    | 文章A | 增量更新 | `02-Wiki/01-科技/Skill生态.md` |
    | 文章B | 新建概念页 | `02-Wiki/03-哲学/xxx.md` |
    | 文章C | 仅索引 | `_index.md` 01-科技 |

11. **用户审核** — 审一次，确认或修改
12. **执行变更** — 用户确认后：
    - 增量更新：正文追加 `### 补充观点`，不覆盖原内容
    - 新建概念页：用 Wiki 模板创建，**同时追加到 `_index.md`**：
      ```bash
      python scripts/safe_link_appender.py --wiki-index --category "01-科技" --entry "[[概念名]] — 摘要"
      ```
    - 仅索引：通过脚本追加
      ```bash
      python scripts/safe_link_appender.py --wiki-index --category "01-科技" --entry "[[文章标题]] — 摘要"
      ```
    - **不涉及任何链接操作**
13. Git 提交

**阶段三：脚本建链 + 移动归档**

14. **扫描全库** — 本次入库文章 + Wiki 概念页 + 已有文章
15. **提关联方案** — 先跑 `python scripts/supplement_linker.py`（补充观点回链+悬空验证），再列关联表格。
    ⚠️ `--new-article` 已内置拦截 Wiki 概念页链入文章。

    | 文章 | 关联文章 | 理由 |
    |------|---------|------|
    | A | B | 同主题 |
    | A | C | 同作者 |
    | B | D | 引用观点 |

    （脚本自动累积去重，多行同文章不怕）

16. **用户审核** — 审一次，确认或修改
17. **脚本建链** — 根据审核通过的表格，逐行构造命令执行：

    转换规则：
    - 每行一条命令，`--new-article --target "文章" --links "关联文章"`
    - 同一篇文章多次调用 → 脚本自动累积去重
    - 涉及 Wiki 概念页 → `--wiki-concept`
    - 索引无概念页 → `--wiki-index`

    实际命令（以上表为例）：
    ```bash
    python scripts/safe_link_appender.py --new-article --target "00-收件箱/A.md" --links "B"
    python scripts/safe_link_appender.py --new-article --target "00-收件箱/A.md" --links "C"
    python scripts/safe_link_appender.py --new-article --target "00-收件箱/B.md" --links "D"
    python scripts/safe_link_appender.py --wiki-concept --target "02-Wiki/01-科技/xx.md" --article "A"
    python scripts/safe_link_appender.py --wiki-index --category "01-科技" --entry "[[A]] — 摘要"
    ```
    ⚠️ 脚本黑名单自动拦截 `01-素材库/` `03-思考/` `04-项目/` `05-产出/` `06-系统/`
18. **移动文件** — `00-收件箱/` → `01-素材库/` 对应分类
19. Git 提交 + 管理日志（附两个方案表格）

### 定期体检

每月执行一次知识库体检：
1. 找出 `#待整理` 超过 7 天的笔记
2. 找出没有任何链接的孤立笔记
3. 找出重复或相似的笔记
4. 汇报给用户处理

---

### Wiki 体检（每周一）

执行 `python scripts/wiki_audit.py`，检查五项：

| 检查项 | 说明 |
|--------|------|
| 🔴 空洞页 | 正文 < 200 字符的概念页 |
| 🟡 孤立页 | 无任何其他文章链接到它 |
| 🔴 断链 | `[[链接]]` 指向不存在的文件 |
| 🔵 缺失概念 | 素材库中被 ≥2 次 `[[提及]]`、但 Wiki 无独立页面 |
| 🟡 过时索引 | `_index.md` 引用不存在的文件 |

脚本给出报告后，AI 再做语义检查：
- 有没有互相冲突的定义
- 有没有已经过期但没被修正的结论
- 有没有经常被提到、却还没有独立页面的概念（已由脚本初筛，AI 进一步判断）

## 🔄 问题路由规则

| 问题类型 | 处理方式 |
|----------|----------|
| 知识库操作（入库、整理） | 直接执行入库流程 |
| Obsidian/插件问题 | 查文档解决 |
| 专业领域问题（Python/AI/法律...） | 找对应专家 Agent |
| 跨多个领域 | 拆解后分别路由 |
| 不知道该找谁 | 先问用户 |

**专家协作流程：**
1. 在 `memory/agents/registry.md` 查询专家列表
2. 整理要转发的内容（笔记路径、问题描述）
3. 使用 `chat_with_agent` 发送给专家 Agent
4. 收到回答后直接转述给用户
