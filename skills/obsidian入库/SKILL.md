# Obsidian 知识库入库流程

当用户说"入库"时，执行此流程。

## 核心原则

1. **只改用户指出的问题** — 用户说哪个文件有问题，只修那个
2. **不批量检查其他文件** — 没有用户要求不主动检查
3. **先读规则和模板** — 不凭记忆干活
4. **操作前 Git 快照，操作后 Git 提交** — 每一次都不例外

## 权限分区

| 区域 | 路径 | 权限 |
|------|------|------|
| 🔵 活动区 | `00-收件箱/` | 自由创建/修改/移动 |
| 🟢 只读区 | `01-素材库/` | 只读，仅可建双向链接 |
| 🔴 禁止区 | `06-系统/` | 禁止修改，除非用户明确允许 |

## 前置条件

1. **读取规则文件** — `D:\Obsidian知识库\知识库\知识库管理指南.md` 和 `AGENTS.md`
2. **⚠️ Git 快照** — 执行 `python scripts/git_control.py pre "入库整理"`
3. **读取模板** — `D:\Obsidian知识库\知识库\06-系统/模板/新笔记.md` 和 `06-系统/模板/Wiki概念页.md`

## 入库流程（三阶段）

> **核心理念**：入库不管链，Wiki 不管链，脚本建链一次审完，建完再移动。

---

### 阶段一：整理入库

#### 第1步：读规则和模板
- 读取知识库管理指南.md 和 AGENTS.md（不凭记忆）
- 读取 `06-系统/模板/新笔记.md` 确认 frontmatter 格式

#### 第2步：扫描收件箱
- 查看 `00-收件箱/` 下所有笔记，列出清单

#### 第3步：阅读内容
- 用 read_file 读取每篇文章的正文，不凭标题猜

#### 第4步：提出分类建议
- 基于内容给出分类建议（01-素材库下子目录）
- **不包含链接建议**（链接留到阶段三统一处理）
- 列出所有文件 + 建议分类，等用户一次性确认

#### 第5步：用户确认后操作
依次：

##### 5a. 修改 frontmatter
按模板格式，所有字段值双引号包裹：
```yaml
---
创建时间: "YYYY-MM-DD"
tags: ["标签1", "标签2"]
类型: "分类名"
状态: "#已整理"
来源: "URL或来源"
作者: "作者名"
摘要: "一句话概括"
---
```

##### 5b. 清理残留
| 模式 | 匹配内容 |
|------|---------|
| `^作者[:：]` | 开头的"作者：xxx"行 |
| `^时间[:：]` | 开头的"时间：xxx"行 |
| `^来源[:：]` | 开头的"来源：xxx"行 |
| `^\d+ 人赞同了该回答` | 知乎赞同行 |
| 正文中单独的 `相关:` / `→ 相关：` | 残留 |
| 重复的 frontmatter 块 | 多余套 |

##### 5c. 正文末尾追加关联文章占位
```

**关联文章**

（待统一建链）
```

#### 第6步：自检
对照模板：
- ✅ frontmatter 字段名、值格式一致
- ✅ 所有字段值双引号包裹
- ✅ `---` 在第1行
- ✅ 正文完整

**自检失败 → rollback + 错误日志 + 终止**

#### 第7步：暂留收件箱
- **不移动文件**，文件留在 `00-收件箱/`
- Git 提交标注 `"入库整理（待建链）"`

---

### 阶段二：编译 Wiki 🔥

#### 第9步：扫描匹配
- 读取 `02-Wiki/` 下所有概念页
- 对每篇入库素材判断是否匹配现有概念

#### 第10步：提 Wiki 变更方案（等用户审核）
按表格列出：

| 文章 | 操作 | 目标 |
|------|------|------|
| 文章A | 增量更新 | `02-Wiki/01-科技/Skill生态.md` |
| 文章B | 新建概念页 | `02-Wiki/03-哲学/xxx.md` |
| 文章C | 仅索引 | `_index.md` 01-科技 |

判断逻辑：
1. **匹配现有概念** → 增量更新（正文追加 `### 补充观点`，不覆盖原内容）
2. **无匹配且有独立价值** → 新建概念页（用 Wiki 模板）
3. **无匹配且内容较浅** → 仅追加 `_index.md`

**阶段二不涉及任何链接操作。**

#### 第11步：用户审核
- 用户审一次，确认/修改 Wiki 变更方案

#### 第12步：执行 Wiki 变更
- **新建概念页**：用 Wiki 模板创建，**同时追加到 `_index.md`**：
  ```bash
  python scripts/safe_link_appender.py --wiki-index --category "01-科技" --entry "[[概念名]] — 摘要"
  ```
- **增量更新**：正文末尾追加 `### 补充观点`
- **仅索引**：
  ```bash
  python scripts/safe_link_appender.py --wiki-index --category "01-科技" --entry "[[文章]] — 摘要"
  ```

#### 第13步：Git 提交
`python scripts/git_control.py post "编译Wiki：N 篇 → {概念页名}"`

---

### 阶段三：统一建链 🔗

#### 第12步：扫描全库 + 自动补回链
- 读取本次入库的全部文章 + 涉及的全部 Wiki 概念页 + 已有文章
- **先跑** `python scripts/supplement_linker.py`：
  - 扫描 Wiki 页 `#### 来自《文章名》` → 全库前缀解析完整文件名 → 插入 `- [[完整文件名]]`
  - 插完验证每条链接精确命中 `.md` 文件

#### 第13步：提关联方案（等用户审核）
按表格列出，**每行一个关联关系**：

| 文章 | 关联文章 | 理由 |
|------|---------|------|
| A | B | 同主题 |
| A | C | 同作者 |
| B | D | 引用观点 |

判断逻辑不变（同主题、同作者、同概念、语义关联）。
脚本自动累积去重，多行同文章不怕。

#### 第14步：用户审核
- 用户审一次，确认/修改链接方案

#### 第15步：脚本建链
根据审核通过的表格，**逐行构造命令**执行：

| 表格行 | → 命令 |
|--------|--------|
| `A \| B \| 同主题` | `--new-article --target "00-收件箱/A.md" --links "B"` |
| 涉及 Wiki 概念页 | `--wiki-concept --target "02-Wiki/xx/概念.md" --article "A"` |
| 索引无概念页 | `--wiki-index --category "01-科技" --entry "[[A]] — 摘要"` |

同一篇文章多次调用自动累积去重。

⚠️ `--links` 必须先 `dir /b` 查真实文件名开头，禁止 AI 缩写。  
⚠️ `resolve_filename` 失败→None→`[REJECT]`，必须回头查 `dir /b` 重跑。  
⚠️ `--new-article` 自动拦截 Wiki 概念页链接。

```bash
python scripts/safe_link_appender.py --new-article --target "00-收件箱/A.md" --links "B"
python scripts/safe_link_appender.py --wiki-concept --target "02-Wiki/01-科技/xx.md" --article "A"
python scripts/safe_link_appender.py --wiki-index --category "01-科技" --entry "[[A]] — 摘要"
```

#### 第16步：移动文件
- 确认无误后，从 `00-收件箱/` 移到 `01-素材库/` 对应分类

#### 第17步：Git 提交 + 管理日志
- `python scripts/git_control.py post "统一建链：N 篇文章，X 条链接"`
- 管理日志附链接方案表格

## 回滚方法

如果入库后发现问题：

- 恢复单个文件：`python scripts/git_control.py restore "00-收件箱/xxx.md"`
- 查看最近提交：`python scripts/git_control.py status`
- 回滚到上一版本：`python scripts/git_control.py rollback`
- 回滚到指定版本：`python scripts/git_control.py rollback <commit哈希>`

## 模板内容

```
---
创建时间: "<% tp.file.creation_date() %>"
tags: []
类型: ""
状态: "#待整理"
来源: ""
作者: ""
摘要: ""
---

# <% tp.file.title %>
```

## 常见错误

| 错误 | 原因 | 正确做法 |
|------|------|----------|
| 三重括号 `[[[` | 链接已包含 `[[...]]`，又加外层 `[]` | 直接写 `[[标题]]` |
| 覆盖正文 | 没 read_file 就 write_file | 先读再写 |
| 多个 frontmatter | 残留的 frontmatter 没清理 | 只保留第一套 |
| frontmatter 红色 | YAML 字段值没用引号包裹 | 所有字段值用双引号 `"..."` |
| 摘要中文引号 | 摘要里用了 `""` | 用单引号 `'...'` 或去掉引号 |
| 文件开头空行 | 用 `split('---\n')` 重建文件导致开头多 `\n` | 用 `edit_file` 追加，不用代码拼接重建 |

## 修改原则

当用户指出某个问题时：
- **只改用户说的那个文件**
- **不主动检查其他文件**
- **不批量修改**
